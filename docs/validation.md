# M5 検証記録: Upstream(物語の層)

2026-11-02 JST。対象Issue #7、ブランチ `m5/scenario-depth`。

## 実装と判断

`src/journey.c` を流体(`fluid.c`)・円盤(`swimmer.c`)の上に足した。物理の式・定数は変えていない。
物語が動かすのは右壁の水門の噴流の強さと、ストロークに使うスタミナの収支だけで、効果ごとに
`JE_*` のビット 1 つで外せる。場面は「区間の開始・区間の通過・最後の区間の中間点」で開き、
死んだ回数のような遊び方で順が割れる条件は使っていない。台詞は `web/app.js`。

| 場面 | 数値 |
|---|---|
| outlet(Silt が拍子を取る) | ストロークの消費 ×0.60(Silt がいる間) |
| culvert(管か水路か) | 管: 噴流 ×1.30 / 水路: 消費 ×0.70、堰で 45 秒待つ |
| eddy(石の陰の渦) | スタミナを 1.25 まで満たす(次の区間) |
| taste(温室の排水) | 回復 ×0.32(第 4 区間) |
| reeds(Silt が葦で止まる) | 以後 Silt なし。残る: 45 秒待ちスタミナ満タン・回復 ×1.40 / 去る: 待ちなし |
| surge(最後の堰板) | 中間点から噴流 ×1.30(去った道は ×1.15) |

流されて取った距離のうち 0.2 を失うと「流された」(失敗)。位置は戻さず、そのつど噴流 ×0.85
(池が空になっていく)。区間に 10 秒かかるごとにも ×0.85 で、詰みは起きない。

# M4 検証記録

2026-10-23 JST。対象Issue #8、ブランチ `m4/swimmer-art`。

## 実装と判断

従来は端末・SVG・GIFだけで原画を描画する面がなかったため、C11のモデルを共有する
ローカルのブラウザー表示層を追加した。独自生成原画は2枚生成・2枚採用。
既存の端末版、CSV、SVG、GIFのコードと参照データには変更を加えていない。
保存機能は元からない。新しい物語・敵・目的は今回の範囲に加えなかった。

## 自動検査

| コマンド・経路 | 実測 |
|---|---|
| `make test`（ネイティブC） | 既存の流体8群・GIF4群が成功、新しい接続層も900ステップの全2,304セルで元のC計算と完全一致。リセット後の水・時刻も0 |
| 同じ `test_view.c` をemccでビルドしてNode実行 | 900ステップ・全セルの完全一致、リセットも成功 |
| `make bench` | 18秒・900行すべてが保存済みCSVと一致。peak speed 0.34419 domain/s、peak Re 51.63 |
| `make web` | WASM 17,953 B、原画を含む配布全体328,843 B・7ファイル。10MB以下 |
| `make smoke` | Chromium、10項目成功。サブパス起動、画像読込、実キーでストローク・旋回・惰性、一時停止、表示切替、フォーカス喪失で入力解除、リセット、デモから手動へ移行、390pxで同時タッチ、画像2枚欠落時の動作 |

通常ページはpage error 0・HTTPエラー0・外部通信0。画像欠落の検査は意図した404で、
警告と円盤・向きの線を表示して計算と操作を続けられた。
モバイル検査ではChromium DevToolsの実タッチ入力で2点を同時に押し、
放した後に入力が残らず、横方向のはみ出しも0だった。実機の代用とはしない。

この実行環境には標準Cヘッダーがなかったため、標準ヘッダーと起動オブジェクトを
一時領域へ展開し、Clang 24 + 既存のシステムリンカーでネイティブ検査を行った。
実行時の `make` には一時ツールチェーンを `CC` で指定した。システムへインストール
していない。Pythonスクリプトは3.14.4。ブラウザー用の物理コードはEmscriptenで検査した。

変更前・変更後の参照CSVはバイト単位でも一致した（下記はSHA-256の先頭12桁）。

```text
SHA-256 prefix: docs/run.csv / baseline/run.csv
a11288283b6d / a11288283b6d
```

ローカル下書きのテスト観点は採否を見直した。原画表示と画像欠落時の継続動作を採用。
本作にいない「敵」の表示、配布10MB境界での実行時フォールバック、README画像数そのものを
動作検査にする案は不適合なので採用しなかった。容量制約はビルド時の実測で検査する。
